إيه هو الـ Software Testing؟

الـ Testing هو التأكد إن البرنامج اللي بنيته بيشتغل صح — في كل الحالات، مش بس الحالة العادية. هو الفرق بين منتج موثوق وآخر بيتعطل على المستخدم.

فكر في الأمر كده

أي عربية قبل ما تطلع السوق بتعدي على آلاف الاختبارات — مكابح، محرك، أمان. ده مش بيحصل عشان المهندسين مش واثقين في نفسهم، ده بيحصل عشان الثقة مش رأي — هي إثبات. الـ Testing في البرمجة هو نفس الفكرة بالظبط.

01

Manual Testing

التستر بيجرب التطبيق بإيده خطوة بخطوة زي المستخدم الحقيقي. بيكتشف مشاكل في الـ UX والـ Edge Cases اللي Automation مش بيلاقيها.

Human Eye
02

Automation Testing

بيكتب كود بيشغّل الاختبارات أوتوماتيك — أسرع، أكثر تكراراً، وبيشتغل مع كل Deployment. ده اللي بيخلي الـ CI/CD يشتغل بثقة.

Robot Speed
03

Performance Testing

بيتأكد إن التطبيق بيتحمل الضغط — آلاف المستخدمين في نفس الوقت من غير ما يبطأ أو يقع. ضروري قبل أي Launch كبير.

Under Pressure
المفهوم الأساسي

هرم الـ Testing

مش كل Test بنفس التكلفة والسرعة. فيه هرم شهير في الصناعة بيقولك امتى تعمل كل نوع وبأي نسبة.

الأساس هو Unit Tests — كتير وسريعة. فوقيها Integration Tests — أبطأ وأشمل. وفوق الكل E2E Tests — الأبطأ لكن الأكمل.

Unit Tests — 70% من وقتك
Integration Tests — 20% من وقتك
E2E Tests — 10% من وقتك
